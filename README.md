# Claude Translator Tool

Конвейер перевода веб-новелл на русский агентами Claude (язык оригинала —
любой распространённый, см. «Язык оригинала» ниже) — костяк,
выращенный на переводе «4.6 миллиарда лет симфонии эволюции» (4884 главы,
полный цикл до выкладки на RanobeLIB). Всё книго-специфичное вынуто; тайтл
подключается через `BOOK.md` + пару констант.

## Быстрый старт

1. Заполни `BOOK.md` (название, BRIEF, **язык оригинала**, источник,
   реквизиты RanobeLIB).
2. `python setup_book.py --apply` — проштамповать тайтл в промпты.
3. Обложка EPUB — `cover.jpg` в корне (необязательно).
4. Константы: `scraper.py` → CATALOG_URL (скрейпер писан под czbooks.net —
   для другого сайта переписать парсинг страницы), `publish_ranobelib.py` →
   SLUG и TEAM_ID, токен в `.ranobelib_token`.
5. Дальше — стадии по порядку.

## Стадии конвейера

| # | Стадия | Команды |
|---|--------|---------|
| 1 | Главы → `chapters/` | из файлов: `python import_text.py book.txt` / `папка/` / `book.epub` (любой язык); с сайта: `python scraper.py` (проверь спам-семейства сайта в `common.py: SPAM_MARKERS/SPAM_SPANS` — у нового сайта будут свои!) |
| 2 | Задания на перевод → `batches/` | `python build_batches.py` |
| 3 | Перевод (флот агентов translator) | `python autorun.py` — один участок; параллельно: `--range LO HI --slot NN` на каждый экземпляр, статус: `python parallel_status.py --watch` |
| 4 | Аудит корпуса | `python verify.py` — структурная приёмка каждой главы (абзацы 1:1, объём, иероглифы, маркеры) |
| 5 | Глоссарий: судейство и арбитраж | `glossary_extract → accumulate → merge`; вердикты — агент judge, конфликты — `build_arbitration.py` + агент arbiter |
| 6 | Правка терминологии | дешёвый первый проход: `morph_rename.py --from Старое --to Новое --range LO HI` (морфология, без агентов); затем `termfix.py` (реестр `term_fixes.json`) → `build_termfix_batches.py` → `termfix_batch_driver.py --slot N` (агент termfix-batch) |
| 7 | Смысловая приёмка (выборочно) | `build_qc.py` → агент proofreader → `build_qcfix.py` → агент qcfix |
| 8 | Финальная сквозная проверка | `python final_check.py` — полнота, структура, спам, канон, глоссарные зонды, нумерация, дубликаты. Ноль провалов и ноль предупреждений = корпус готов |
| 9 | Выкладка | `publish_ranobelib.py --publish [--range LO HI]`; синк правок: `--sync --publish`; капельная выкладка: `passive-update.py --every N` |
| 10 | Карта мира (опционально) | скелет co-occurrence + агенты glossmap → ревизия glossmapcheck → `build_reader_map.py` → страница с поиском и связями |
| 11 | EPUB (опционально) | `python build_epub.py` |

## Уроки, оплаченные кровью (зашиты в код, не выключай)

- **Приёмка каждой главы** (`common.validate_translation`): абзацы строго 1:1
  с оригиналом, коэффициент объёма 2.0–4.5, ≤2 иероглифов, никаких служебных
  маркеров/тегов. Каждая правка любой стадии проходит через неё с откатом.
- **Никаких regex-правил по нарицательным словам.** Правило «сущест\w* →
  Капитаны» однажды превратило «существовало» в «Капитаны». `termfix.py`
  снимает правила, ловящие собственный канон, и требует зону глав; пустая
  зона = правило снято, а не «применять везде».
- **Гистограмма замен** — главный детектор вандализма: пословный дифф
  «рождение главы → сейчас» по git (см. `repair_vandal.py` за движком
  точечного отката). Скан ловит только ОСТАВШИЕСЯ варианты; нанесённую порчу
  видно только диффом.
- **Файл замен пользователю на вычитку** после каждой массовой правки —
  человек за полминуты видит класс ошибок, который агенты пропустят.
- **Выравнивание по CN**: точечные правки строить от позиций китайского
  термина через выравнивание абзацев 1:1, а не regex по русскому тексту.
- **Спам-семейства сайта** проявляются волнами до самого конца (у czbooks их
  было восемь, включая рекламу веб-игры, переведённую агентами восемью
  разными способами). Любой странный заголовок/абзац — повод для грепа по
  обеим сторонам корпуса.
- **Замок выкладки** (`.publish_lock`) — два паблишера параллельно дерутся за
  журнал; пассивный публикатор сам ждёт снятия замка.
- **Правки журналов только при остановленных паблишерах** — гонка за
  `ranobelib_published.json` затирает записи молча.
- **Агентам-правщикам — Edit, не Write**: вывод в разы дешевле и исчезает
  класс поломок «служебные теги в тексте». Точечное чтение — Read с
  offset/limit по номерам строк из задания.

## Структура

- `.claude/agents/` — 13 агентов: translator, judge, arbiter, proofreader,
  qcfix, fixer, termfix, termfix-batch, glossfix, glossjudge, glossmap,
  glossmapcheck, termaudit. Книго-контекст штампуется из BOOK.md.
- Драйверы флотов (`*_driver.py`) — атомарные claim-файлы, поглавная
  приёмка, `откат битого к снимку, журнал расходов `termfix_usage.jsonl`.
- `config_ui.py` — пульт (streamlit), `launcher_console.py` — диспетчер задач.

## Язык оригинала

Строка `- Язык оригинала (код): ko` в `BOOK.md` переключает весь конвейер;
всё языкозависимое собрано в `lang.py`. Коды: `zh ja ko en es fr de pt it nl
pl tr vi id th ar fa he hi uk`, неизвестный код — общий профиль алфавитного
языка. `python lang.py` показывает действующий профиль. От языка зависят:

- **приёмка**: норма объёма перевода, какие знаки считаются непереведённым
  остатком (иероглифы, хангыль, кана…; для латинских языков — фразы от
  четырёх латинских слов подряд, имена и бренды латиницей допустимы);
- **номера глав** в заголовках: `第12章`, `第12話`, `12화`, `Chapter 12`,
  `Capítulo 12`, `Глава 12`… и склейки двух глав под одним заголовком;
- **кандидаты в глоссарий**: n-граммы знаков (zh, ja, th), слова со снятыми
  падежными частицами (ko), слова (ar, fa, he, hi), цепочки слов с заглавной
  (алфавитные языки); конструкции именования («назвали X») — для zh, ja, ko
  и основных европейских;
- **промпты агентов**: язык и система транскрипции имён (Палладий, Поливанов,
  Концевич, практическая) штампуются `setup_book.py`.

**Нормы объёма замерены только для китайского (2.0–4.5).** Для остальных
языков стоят оценки с запасом. После 10–20 вычитанных глав запусти
`python lang.py --measure` и впиши предложенную строку «Норма объёма» в
`BOOK.md` — иначе приёмка либо пропустит пересказ, либо забракует честный
перевод. Язык перевода — всегда русский.

Что остаётся китайским: спам-фильтры `common.py` (семейства czbooks),
`scraper.py`, примеры калек в промпте proofreader. На другом языке они просто
не срабатывают; свои спам-маркеры сайта добавляй в `SPAM_MARKERS/SPAM_SPANS`.

## Морфология

Две независимые вещи, обе на необязательных библиотеках (`requirements.txt`).

**Переименование в готовом переводе — `morph_rename.py`** (pymorphy3 +
natasha). Меняет имя сущности с падежом и числом, по синтаксическому дереву
переставляет род определений и сказуемого, правит предлог (со/с, об/о).
Локально, секунды на главу, без токенов:

```
python morph_rename.py --from Защитник --from Стражник --to Страж --range 37 54
python morph_rename.py --from Страж --to Тень --range 1 90 --apply --resolve
```

Чего он не делает и честно откладывает в `morph_doubt.json`: местоимения
(«Страж вошёл. Он сел» — дерево не выходит за предложение), придаточные с
«который», совпадающие родительный и винительный («боялись Стража» /
«увидели Стража» — у нового имени формы разные, а выбирает их управление
глагола). С `--resolve` отложенные абзацы уходят дешёвой модели (роль
`haiku` активного провайдера) по короткому запросу на абзац; что не далось и
ей — агентам termfix. Каждая глава проходит приёмку, список замен ложится в
`replacement_morph.txt` — **пролистай его**: синтаксический парсер ошибается
уверенно, и такие ошибки ловит только глаз. Чего он не умеет в принципе:
понять, что «ящер из пыли» и «Пылевой крокодил» — одно существо, или развести
двух существ под одним именем. Это по-прежнему глоссарий и арбитраж.

**Морфология языка оригинала** (`lang.py`, класс `Morph`): `kiwipiepy` для
корейского, `janome` для японского, `simplemma` для en es fr de pt it nl pl
tr id uk fa hi. С ней кандидаты в глоссарий считаются по словарной форме
(Wächters = Wächter, 린은 = 린), а термин глоссария находится в главе и в
косвенной форме — и попадает в задание переводчику. Китайскому, вьетнамскому
и тайскому она не нужна; для арабского и иврита лёгкой библиотеки нет. Без
библиотеки всё работает как раньше, грубее; `python lang.py` подскажет, что
поставить.

## Провайдер модели: подписка или API-ключи

По умолчанию агентов запускает `claude` CLI на подписке Claude. Переключение —
одной командой, все флоты (`autorun.py`, `*_driver.py`) подхватывают его сами:

```
python llm.py list                              готовые профили
python llm.py use anthropic                     API-ключ Anthropic вместо подписки
python llm.py use openrouter --model ИМЯ        другой провайдер, одна модель на все роли
python llm.py use openai --sonnet A --opus B    разные модели по ролям
python llm.py key openrouter                    ввести ключ (скрыто, ляжет в .env)
python llm.py test                              пробный вызов
python llm.py use subscription                  назад на подписку
```

Готовые профили: `subscription`, `anthropic`, `deepseek`, `zai`, `moonshot`
(через `claude` CLI — у этих провайдеров Anthropic-совместимый API) и
`openai`, `gemini`, `openrouter`, `xai`, `groq`, `mistral`, `together`,
`ollama` (OpenAI-совместимый API). Любой свой шлюз:
`python llm.py use ИМЯ --base-url URL --key-env ПЕРЕМЕННАЯ --model МОДЕЛЬ`
(добавь `--protocol anthropic`, если шлюз говорит на API Anthropic).

Для OpenAI-совместимых провайдеров `claude` не нужен: агента ведёт
встроенный цикл `llm_agent.py` — те же промпты `.claude/agents/*.md`, те же
инструменты (Read, Write, Edit, Bash, Grep, Glob; файлы только внутри
проекта), тот же формат отчёта. Скрипты просят роль (`opus`, `sonnet`,
`haiku`), профиль отображает её на модель провайдера; имён чужих моделей в
коде нет — их задаёшь ты.

Ключи читаются из переменной окружения профиля или из `.env`; оба файла
настроек (`.env`, `.llm.json`) в `.gitignore`. Особые параметры запроса
(например, лимит вывода) — поле `extra_body` профиля в `.llm.json`.

Чего ждать: приёмка глав от провайдера не зависит, так что слабая модель даст
больше брака и повторов, а не испорченный корпус. Стоимость в журнале расходов
считается, только если провайдер сам присылает её в ответе (OpenRouter);
иначе там токены без долларов. `translate.py` (прямой перевод без агентов)
по-прежнему работает только с API Anthropic.

## Чего в каркасе нет (собирается под тайтл)

- Сборщики заданий для флотов `glossmap`, `glosscheck`, `termaudit`
  (`<папка>/task_index.json` + `task_NNN.md`) и скелет карты мира
  `glossmap/skeleton.json` / сведённый `glossmap/merged.json` — драйверы и
  `build_reader_map.py` их только читают.
- `replacement_detail.json` (гистограмма замен для `repair_vandal.py`) строится
  пословным диффом по git; движку отката нужен `ru/` под git — в этом
  каркасе `ru/*` в `.gitignore`, для vandal-аудита сними исключение.
- Книго-специфичные правила `repair_vandal.py` (`classify`, `CONTEXT_REPAIRS`,
  `ERSH_*`) и `TARGET_CN` в `build_glossfix.py` — примеры прошлого тайтла,
  заменить своими.

## Запуск задач на Linux

`python main.py` (диспетчер) на Windows открывает задачу в окне PowerShell
(`launcher_worker.ps1`), на Linux/macOS — запускает в фоне своей сессией с
журналом `logs/<задача>.log`; остановка — пунктом меню. Участки параллельных
слотов `autorun.py --range LO HI --slot NN` пишет сам в
`parallel_range_NN.json`, их читает `parallel_status.py`.
